## Failure analysis
1. **Session-expired on reused sessions (resolved by redesign).** Saved browser state was rejected with `reason=session-expired`. The suite now logs
   in once per account and reuses that tab (see AUTO-RISK-01).
2. **Composer locator (fixed in code, to be re-verified).** `ComposerPage.open()` waited for a composer root test id that does not exist;
   "composer is open" now means the subject field is visible.
3. **Remaining failures** are expected to be selector differences on the live UI. On every failure the framework saves a screenshot
   (`reports/screenshots`), a trace (`reports/traces`) and `reports/diagnostics/*.txt`, which lists the real `data-testid` values and
   button labels on the page, so each fix is a one-line change in `Locators.java`.
